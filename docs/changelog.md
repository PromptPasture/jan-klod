# Changelog

## 2026-10-24

- **Chore**: **Wasmtime builds only the features the host uses** ([#307](https://github.com/PromptPasture/jan-klod/issues/307)). The root `Cargo.toml` turns off `wasmtime`'s and `wasmtime-wasi`'s default features and keeps `std`, `runtime`, `cranelift`, `component-model`, `cache`, `parallel-compilation`, `wat`, `backtrace`, and WASI `p2`; each is commented with the host code that needs it. Dropped: GC, async Component Model, threads, stack-switching, profiling, coredump, debug, pooling, WASI `p1`/`p3`, and `addr2line`/`demangle`/`anyhow` (guests ship stripped, and no `bindgen!` sets `anyhow`). Measured on Wasmtime 49.0.2 (before #311), Linux x86_64, 16 cores, clean `CARGO_TARGET_DIR`, one run each: clean `cargo build --workspace` 64.3 s / 2606 MB → 53.8 s / 2146 MB; then `cargo test --workspace --features jk-host/integration --no-run` 55.9 s / 6174 MB → 45.2 s / 4901 MB; clean release build 125.0 s → 102.5 s; `jan-klod-gateway` 61.1 MB → 43.8 MB; unique normal dependencies 320 → 298. `make gate`: 956 passed, 2 skipped; `cargo nextest list` names the same 956 tests before and after.
- **Security**: **Wasmtime 49.0.4 and the patched rustls stack clear 21 advisories** ([#311](https://github.com/PromptPasture/jan-klod/issues/311)). `cargo update` moved `wasmtime`/`wasmtime-wasi` 49.0.2 → 49.0.4 (with their exact-pinned `cranelift-*`, `pulley-*`, `wasmtime-internal-*` and `wiggle*` siblings), `rustls` 0.23.45 → 0.23.46, `rustls-webpki` 0.103.15 → 0.103.16 and `webpki-roots` 1.0.8 → 1.0.11. All are patch releases, and `Cargo.lock` is the only file that changed. The two that could matter here: a WASI filesystem sandbox escape (RUSTSEC-2026-0352), which guests can't reach today because they get no preopened directories, and a Cranelift wrong jump on aarch64 (RUSTSEC-2026-0379). `make audit` now passes. `make gate`: 956 passed, 2 skipped, with the same test names as before.
- **Security**: **`make deny` passes again** ([#312](https://github.com/PromptPasture/jan-klod/issues/312)). `tokio` 1.52.3 → 1.54.1 (RUSTSEC-2026-0386, unsound `AsyncFd` constructors; nothing in this repo calls them) and `lru` 0.18.0 → 0.18.5 (RUSTSEC-2026-0253, via `ratatui`) are patch bumps. `unsafe-libyaml` (RUSTSEC-2024-0449, unmaintained, no advisory against its code) reaches us through `serde_yaml_ng`. It gets a commented host-side entry in `deny.toml`'s ignore list, because replacing the YAML parser changes how every `config.yaml` is read. That decision stays open in #312.

- **Fix**: **a `host_process` test no longer sets `TMPDIR` for the whole test process** ([#297](https://github.com/PromptPasture/jan-klod/issues/297)). `a_commands_temp_directory_is_inside_the_workspace` pointed `TMPDIR` at a non-existent root path, so under plain `cargo test` (threads in one process) every later test fixture under `env::temp_dir()` failed, 49–52 per run. nextest isolates each test, which hid it everywhere but the macOS job. The assertion never needed the sentinel.

It now installs the same pin as `ci.yml`.
- **Refactor**: **Phase 21 — packages renamed to `jk-*`** ([#183](https://github.com/PromptPasture/jan-klod/issues/183)). `jan-klod-protocol` → `jk-protocol`, `jan-klod-config` → `jk-config`, `jan-klod-host` → `jk-host`, the TUI package `jan-klod` → `jk-tui`, `jan-klod-gui` → `jk-gui`; crate paths follow (`jk_protocol::…`, `jk_host::…`). Binary names are unchanged — `jan-klod`, `jan-klod-gateway` and `jan-klod-gui` — so `install.sh`, `bundle.sh` and release archives are untouched; extension crates and the `jan-klod:*` WIT package keep their names. Gate: `make gate`; `make bundle DIST=coding` ships `jan-klod` and `jan-klod-gateway` as before.
- **Refactor**: **Phase 21 — `jan-klod-core` retired; the harness is `jk-agent`** ([#182](https://github.com/PromptPasture/jan-klod/issues/182)). `pkgs/host/agent` holds the conductor, `AgentSession`, delegation and the wiring of `jk-wasm` to `jk-session` — 2,877 lines. [Architecture](concepts/architecture.md) no longer claims a ~200-line loop: the conductor is 548 non-test lines, and the case for a native loop is the trusted host and the double WASM boundary. Loop semantics unchanged. Gate: `cargo tree -p jk-agent` names no HTTP server or JSON-RPC crate.
- **Refactor**: **Phase 21 — the component runtime is `jk-wasm`** ([#181](https://github.com/PromptPasture/jan-klod/issues/181)). Boot, the linker, every `host-*` capability, manifests, the effect sandbox, egress, the registry and the compile cache moved to `pkgs/host/wasm`, the one crate naming `wasmtime`. `Runtime::instantiate` returns interceptors, providers and tools and takes guest storage as a closure, so `jk-wasm` never names `jk-session`. No capability refusal, manifest check or signature check changed; [security model](concepts/security-model.md) rows cite the new paths, and `egress_boundary::every_guest_facing_backend_goes_through_the_policy` scans `pkgs/host/wasm/src`.
- **Refactor**: **Phase 21 — `jk-session` callers use the real paths** ([#180](https://github.com/PromptPasture/jan-klod/issues/180)). `jan-klod-core` no longer re-exports `jk_session::{event_log, projection, store}` or the turn vocabulary in `conductor`/`intercept`; every caller names `jk_session::…` and `jan_klod_protocol::turn::…` directly. No behaviour, schema or event-envelope change. Gate: `cargo tree -p jk-session` names no `wasmtime`; the Phase 14 exit gate (`pkgs/host/host/tests/it/event_log.rs`, `pkgs/host/session/tests/store.rs`) passes.
- **Fix**: **`--version` and `--help` on both binaries** ([#247](https://github.com/PromptPasture/jan-klod/issues/247)). `jan-klod-gateway` read either flag as a config path and fell through to the boot plan; `jan-klod` refused them as unknown options. Both now print the version (`CARGO_PKG_VERSION`) or a usage listing every subcommand, and exit 0. Tests: `pkgs/host/host/tests/it/info_flags.rs`, `pkgs/clients/tui/tests/info_flags.rs`.
- **Chore**: **Markdown lint** ([#234](https://github.com/PromptPasture/jan-klod/issues/234)). `make lint-docs` runs `markdownlint-cli2@0.23.3` over every tracked `.md` against `.markdownlint.yaml`; the pre-commit hook runs it when a `.md` is staged, and CI runs it beside `test-web`. MD060 is off because the house table style (padded cells, tight delimiter row) matches none of its styles. Existing findings fixed: whitespace, blank lines around blocks, `$` prompts dropped from output-less `console` blocks, one broken anchor.

## 2026-09-20

- **Implement**: **Slice 28e — Telegram sender allowlist: the sender id the Bot API asserts becomes the principal `telegram:<sender_id>`** (#257). `headless-chat` ships `telegram.allowed-senders: []` empty by default, refusing all senders until an operator explicitly lists them. Before a session is created, an unlisted sender is refused with a log message. The principal is passed through `run_with_driver_principal` to the conductor for downstream access in the interceptor. Test: `host/tests/it/telegram.rs::telegram_sender_allowlist_refuses_unlisted_and_accepts_listed`.

- **Implement**: **Slice 28c — principal reaches interceptors: the optional `principal` field on `user-turn`** (#255). The WIT contract (`wit/interceptor.wit`) adds `principal: option<string>` to the `user-turn` record handed to guests at the `before-loop` phase. Established by slice 28a (the principal is resolved from the bearer token in the REST/WebSocket guard and inserted into request state), the value reaches the conductor's `run_turn` function, is passed to `build_initial_request`, and flows to the guest via the interceptor host mapping. A guest may read this to make data-driven decisions (route to specific models, log the principal, redact it) — all policy encoded in config or guest heuristics, never inside the host. The API_VERSION bumped from 0.3.0 to 0.4.0 to reflect the contract change.

- **Implement**: **Slice 31c — capability groups as data, selected and merged by union, for setup and the Configurator** (#270). `scripts/capabilities.yaml` defines named groups of extensions that work together: `reasoning` (required, core agent phases), `content-guard`, `provider-openai`, `provider-anthropic`, `file-tools`, `version-control`, `shell-access`, `web-fetch`, `plan-analyze`, and `ecosystem`. A `pending` section documents Phase 30 guests not yet built (`tool-memory`, `tool-web-search`, `interceptor-persona`, `agent` category). Groups compose by union; per-instance naming resolves conflicts when two groups enable the same extension with different config. Validation tests in `src/config/tests/capabilities_validation.rs` verify YAML well-formedness, member existence, and merge logic.

- **Implement**: **Slice 30g — first-party skills ship inside the distribution archive** (#267). `registry-skills` now merges skills from two sources in priority order: `.agents/skills/` (workspace level, user override) checked first, and `skills/` (distribution level, bundled fallback) checked second. `scripts/bundle.sh` copies skill files into archives. Each distribution (`coding`, `headless-chat`, `minimal`, `self-extend`) ships three first-party skills: `commit.md` (clear commit message guidance), `review.md` (code review checklist), and `plan.md` (task breakdown patterns). The test `registry_skills_loads_bundled_and_workspace_overrides` verifies bundled skills are loaded and workspace override behavior works correctly.

- **Implement**: **Slice 30c — interceptor-persona: personality as data, read from config at select-model** (#263). The extension reads a configured default persona at init time and injects it into each turn's context before model selection at the `select-model` phase.
