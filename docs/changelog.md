## 2026-07-06

- **Refactor**: **Guest extensions merged into one Cargo workspace.** [src/extensions/Cargo.toml](../src/extensions/Cargo.toml) is now a real workspace for all 13 first-party Rust guests — shared `workspace.dependencies` (`wit-bindgen`, `serde_json`, `whatlang`), shared `workspace.lints` (each guest previously declared the strict policy locally, since guests lived outside any workspace), and one `[profile.release]` (`opt-level = "s"`, `strip`, `lto` — Cargo profiles only apply at a workspace root, so this moved out of each guest's own `Cargo.toml`). Consolidated the 13 per-guest `Cargo.lock` files into one shared lock. Disk: one target dir (169MB) instead of 13 separate ones (~4.5GB total). [src/extensions/Makefile](../src/extensions/Makefile): `audit`/`deny` now run once for the whole workspace instead of looping per guest; `deny.toml`'s stale "each guest has its own Cargo.lock" comment corrected.
- **Optimize**: **Extension builds run in parallel.** `make -C src/extensions all` now builds all 13 guests in one `cargo build` invocation instead of 13 sequential `make` recipes, letting cargo's own scheduler compile independent guests concurrently across cores — cold build dropped from ~26-30s to ~14s. `make <guest-name>` still builds a single guest standalone for targeted dev iteration.
- **Fix**: **`src/core` debug builds were consuming 48GB, 15GB of it stale incremental cache.** `cargo clean` reclaimed 80.9GiB; added `[profile.dev] debug = "line-tables-only"` to [src/core/Cargo.toml](../src/core/Cargo.toml) to keep it from growing back — backtraces still resolve to file:line, full variable inspection in a debugger is reduced.
- **Fix**: **Pre-commit hook faster fail-fast.** Added a `check` target to [src/core/Makefile](../src/core/Makefile) (`cargo check` — no codegen/linking) and pointed [.github/hooks/pre-commit](../.github/hooks/pre-commit) at it instead of `build`: `cargo test` (which runs right after in the same hook) already does the real build, so the prior `cargo build` step was redundant work.
- **Fix**: **Lockfile-freshness check de-duplicated.** [.github/hooks/pre-push](../.github/hooks/pre-push) and [.github/workflows/ci.yml](../.github/workflows/ci.yml) globbed `src/extensions/*/Cargo.toml` (13 identical checks against the same now-shared lock); both now check `src/extensions/Cargo.toml` (the workspace root) once.

## 2026-07-01 (session 31)

- **Decide**: **Thin loop + interceptor middleware** — after reviewing [earendil-works/pi](https://github.com/earendil-works/pi), re-architected the agent loop. Keep the foundation (sandbox + small models + everything-WASM + nothing-trusted) but adopt Pi's astonishingly-thin loop as **core mechanism**: the loop (`stream → tools → loop`, grammar passthrough, parse/validate/retry-with-correction, streaming handles, cancel, steering/follow-up queue, tool-result `terminate`) moves into **core** and holds **zero policy**. Every decision becomes a sandboxed **`interceptor-*`** extension (each exports the `interceptor` interface) consulted at fixed lifecycle points (`before-loop`, `prepare-request`, `tool-call`, `tool-result`, `prepare-next-turn`). Dispatch is **core-native** — the loop calls the exported interface directly, ordered via `jan-klod.yaml` (no `host-hook` capability; distinct from the observation-only `host-event` bus). Small-model harness split: constrained-decoding grammar + retry/validate stay fixed core mechanism, tuned via `host-config` + the shared `prepare-request` seam. **Provider fallback** is core mechanism too (it re-issues the same failed request). `manager-agent-loop` (and `agent-manager.wit`) retired; `manager-context` → `interceptor-context` (with `context-manager` subsumed as internal). v1 interceptor set: intent-router, task-router (classification + routing), tool-selector (thin), context (compressor), permission (thin). A `/review` pass then reconciled three points (core-native dispatch; generic-hook-only context; fallback→core) — see the post-review section of the record. Recorded in [decisions/2026-07-01-thin-loop-interceptors/BRAINSTORM.md](decisions/2026-07-01-thin-loop-interceptors/BRAINSTORM.md).
- **Refine**: **Interceptor contract drafted + lifecycle expanded to an ordered `phase` enum.** After a second Pi pass, the single `prepare-request` hook was split into ordered request-shaping sub-phases (`select-model` → `select-context` → `select-tools`) and `session-start`, `after-response`, `finalize` were added — **many narrow phases over few broad ones**, so ordering between concerns is *structural* (the phase enum), not a config-fragile contract. Drafted [`wit/interceptor.wit`](../wit/interceptor.wit): one generic `intercept` over a `phase` enum + `subscribed-phases`, return `result<decision, interceptor-error>` where `decision = proceed | replace | block | ask`. New **`ask`** decision routes a question through the loop to the attached driver and resumes on the answer — resolves the old **UI-gap** open question (a rule-based permission gate confirms with the user without touching a UI). Error/trap policy: **fail closed at `tool-call`**, fail-open-with-log elsewhere. **Ordering is not configurable** — `jan-klod.yaml` only enables/disables. Streaming reconciled via **preview-vs-authoritative** (streamed tokens are a preview; `after-response`/`finalize` may `replace` the authoritative message). A `/review` pass drove three fixes into the contract (error result type; `finalize`-vs-streaming; `llm-provider` import for classifier/summariser interceptors). Updated [architecture.md](concepts/architecture.md) (loop diagram + phases), [contracts.md](concepts/contracts.md), [roadmap.md](concepts/roadmap.md), [small-model-harness.md](concepts/small-model-harness.md), and the [decision record](decisions/2026-07-01-thin-loop-interceptors/BRAINSTORM.md) (Decision 4 rewritten; UI-gap/WIT-shape/ordering open questions resolved). **Rewrote the Phase 2 plan** [decisions/2026-07-01-phase2-agent-loop/PLAN.md](decisions/2026-07-01-phase2-agent-loop/PLAN.md) around the new architecture — re-sliced into: 2a intent-router **recast** as `interceptor-intent-router`, 2b `interceptor` contract + **core-native dispatch framework**, 2c **core loop mechanism** (conductor + harness + fallback + run entry), 2d the **v1 interceptor set** (task-router/context/tool-selector/permission), 2e exit gate; retirement of `manager-agent-loop`/`agent-manager.wit`/`agent-loop.wit`/`context-manager.wit` tracked as slice tasks.

## 2026-06-29 (session 30)

- **Implement**: **`provider-openai` — the second Rust guest, and the first network extension.** OpenAI-compatible implementation of `llm-provider` (`complete`/`next-chunk`/`close-stream`/`info`) plus `extension-lifecycle`, in [src/extensions/provider-openai/](../src/extensions/provider-openai/). `init` reads `base-url`/`api-key`/`model` from `host-config` (never logs the key); `complete` builds a Chat Completions request, issues **one blocking `host-http::fetch`** (non-streaming — `host-http` buffers the whole body, so SSE would add parsing for no latency win), parses `choices[0].message` into ordered completion chunks (`tool-call-request`s or a `text-delta`, always closed by `done`), and buffers them under a stream handle the host drains. Built via `make provider-openai` / `make provider-openai-docker`.

Per the `host-http` contract, 4xx→`client-error`, 5xx→`server-error`, transport failures→the matching variant. The core's `host-http::Host` and the new probe example both adapt their generated types to this one neutral implementation. 2 status-mapping unit tests.
